# pop-Eyes — подбор подрядчиков для мероприятий

Заказчик задаёт город, дату, формат, категорию, бюджет и, при желании, язык, длительность и пожелания. Цель MVP — показать до трёх подходящих подрядчиков с объяснениями выбора. Правила допуска и ожидаемый сценарий описаны в [плане хакатона](docs/HACKATHON_PLAN.md).

## Что готово сейчас

Есть [одностраничный интерфейс](frontend/index.html) с формой и демонстрационными ответами для подбора, отсутствующей категории, отсутствия подходящих подрядчиков и резервного режима. **Это примеры отображения, не настоящие рекомендации.** Интерфейс пока не обращается к API и не использует данные каталога.

Для просмотра откройте `frontend/index.html` в браузере. Выберите «Пример ответа», заполните обязательные поля и нажмите «Показать пример результата». Сервер и зависимости для этого не нужны.

## Контракт для подключения API

Планируемые маршруты: `GET /api/options` для значений формы и `POST /api/recommendations` для подбора. Форма готовит запрос с полями `city`, `date`, `event_type`, `category`, `budget_kzt`, `duration_hours`, `language`, `preferences`. Необязательные язык и длительность передаются как `null`.

Интерфейс ожидает `status` (`matched`, `category_absent`, `no_matches`), `message`, `cards`, `eligible_count`, `selection_mode` (`ai` или `fallback`). Для карточки используются `id`, `name`, `categories`, `city`, `price_from_kzt`, `reason`. Точные имена полей карточки и справочника `/api/options` необходимо согласовать с участником backend перед подключением.

## Дальше

После появления backend подключить справочники и настоящую отправку формы, загрузку и ошибки, затем проверить контрольные запросы из [аудита данных](docs/DATA_AUDIT.md). Команды запуска полного приложения через Docker Compose будут добавлены только после проверки работающей сборки.
# pop-Eyes — подбор event-подрядчиков

Проект команды pop-Eyes Team для HackAlem AI. Цель — подобрать до трёх подрядчиков под условия мероприятия и объяснить выбор с учётом пожеланий заказчика.

## Текущее состояние

Реализован первый этап backend:

- Docker Compose с FastAPI и PostgreSQL 16.
- SQL-схема и автоматический импорт всех 66 профилей из предоставленного CSV.
- Сохранение данных в Docker volume, повторный импорт без дублирования ID.
- Проверка готовности приложения и данных: `GET /health`.
- Справочники для формы: `GET /api/options`.
- Чтение отдельного профиля: `GET /api/contractors/{contractor_id}`.
- Swagger UI и интеграционные проверки сохранности данных.

Следующий этап: `POST /api/recommendations`, строгие фильтры, AI-выбор TOP-3, сохранение решений и пользовательский интерфейс. Они пока не реализованы. В текущей версии внешние AI API не вызываются и ключ не требуется. Публичного deployment пока нет.

## Быстрый запуск

Нужен запущенный Docker Desktop с Linux containers и Docker Compose. Python и PostgreSQL на компьютер устанавливать не нужно.

Из корня репозитория в PowerShell:

```powershell
Copy-Item .env.example .env
# Откройте .env и задайте свой POSTGRES_PASSWORD.
docker compose up --build -d --wait
```

Если `.env` уже существует, используйте его и не перезаписывайте командой копирования. При занятом порте измените `APP_PORT` в `.env`.

После запуска:

- [Swagger UI](http://localhost:8000/docs)
- [Проверка готовности](http://localhost:8000/health)
- [Параметры формы](http://localhost:8000/api/options)
- [Пример профиля](http://localhost:8000/api/contractors/HK-39372)

Ссылки приведены для `APP_PORT=8000`. Приложение доступно только на локальном компьютере. PostgreSQL доступен сервису `app` как `db:5432`, порт базы на компьютер не опубликован.

Ожидаемый ответ `/health`:

```json
{
  "status": "ok",
  "database": "ok",
  "profiles_count": 66,
  "dataset_version": "<SHA-256 нормализованного каталога>"
}
```

`/health` проверяет доступ к БД, наличие метаданных, непустой каталог и совпадение количества профилей. При недоступной БД или незавершённом импорте возвращается HTTP 503.

## Как поднимается среда

```text
docker compose up --build
  → PostgreSQL создаёт базу из POSTGRES_DB
  → db/init/001_schema.sql создаёт таблицы и индексы
  → db/init/002_seed.sql читает CSV и загружает профили
  → PostgreSQL проходит healthcheck
  → FastAPI подключается к db:5432
  → /health подтверждает готовность данных
```

Для PostgreSQL используется готовый официальный образ, поэтому отдельный Dockerfile базы не нужен. Корневой `Dockerfile` собирает Python-приложение.

Скрипты `/docker-entrypoint-initdb.d` выполняются автоматически **только при создании пустой базы**. Обычный перезапуск сохраняет данные и не повторяет импорт. Это поведение [официального образа PostgreSQL](https://hub.docker.com/_/postgres).

## Данные и схема

Источник: [hackathon dataset anonymized .csv](hackathon%20dataset%20anonymized%20.csv). HTML-превью не используется как источник данных.

Таблица `contractors` сохраняет все 13 полей:

| Поле | Тип в PostgreSQL |
| --- | --- |
| `id` | `TEXT PRIMARY KEY` |
| `anon_name`, `city`, `description` | `TEXT` |
| `categories`, `event_formats`, `languages` | `TEXT[]` |
| `city_imputed`, `synthetic`, `price_imputed` | `BOOLEAN` |
| `price_from_kzt` | `BIGINT` |
| `max_hours` | `NUMERIC`, допускает `NULL` |
| `busy_dates` | `DATE[]` |

Промежуточная временная таблица принимает CSV стандартной командой `COPY`: кавычки, запятые и переносы строк в описаниях обрабатываются CSV-парсером PostgreSQL. Списки с разделителем `|` преобразуются в массивы. Пустой `max_hours` сохраняется как `NULL`.

Таблица `dataset_metadata` хранит календарное окно, количество профилей, время импорта, SHA-256 исходного файла и версию фактически загруженного каталога. Повторный импорт тех же данных не меняет `dataset_version`.

Импорт выполняется в транзакции. Неверные типы, повторные ID в CSV, несовпадение заголовка, пустой файл или даты вне известного окна приводят к ошибке и откату импорта.

Ограничения данных:

- Доступность известна только с **23.09.2026 по 31.12.2026 включительно**.
- Цена — «от» за мероприятие, не окончательная стоимость.
- `max_hours=NULL` означает неприменимость ограничения присутствия, не ноль часов.
- В исходном наборе 13 синтетических профилей, 8 подставленных городов и 18 подставленных цен; флаги сохранены.

Подробности: [DATA_AUDIT.md](docs/DATA_AUDIT.md).

## Повторный импорт и управление

После правки CSV выполнить повторный импорт. Для нестандартных пользователя и имени БД подставьте их значения из `.env`:

```powershell
docker compose exec db psql -U eventmatch -d eventmatch -v ON_ERROR_STOP=1 -f /docker-entrypoint-initdb.d/002_seed.sql
```

Импорт добавляет новые ID и обновляет существующие. Записи, отсутствующие в новом CSV, автоматически не удаляются. Если после изменения CSV запускаете тесты сверки, пересоберите `app`, чтобы обновить копию тестового источника в образе.

Изменения схемы не применяются к существующей БД автоматически. Текущий `001_schema.sql` можно повторить той же командой с другим именем файла; он создаёт недостающие таблицы и индексы. Будущие изменения существующих столбцов потребуют отдельной SQL-миграции.

```powershell
# Логи без вывода переменных окружения.
docker compose logs --tail=50 app db

# После изменения Python-кода.
docker compose up --build -d --wait

# Перезапуск приложения.
docker compose restart app

# Остановка контейнеров с сохранением базы.
docker compose down

# Запуск с сохранённой базой.
docker compose up -d --wait
```

Том `pop-eyes_postgres_data` сохраняет БД после `down`. Не добавляйте `--volumes`, если данные нужно сохранить. Изменение пароля в `.env` не меняет пароль уже созданной базы: его нужно менять отдельно в PostgreSQL.

Если первичная инициализация остановилась на ошибке SQL, проверьте логи. После исправления можно запустить `db` и явно выполнить `001_schema.sql`, затем `002_seed.sql` через `psql`; повторный старт контейнера сам не продолжит прерванные init-скрипты.

## Структура и следующий этап

```text
app/
  main.py            # HTTP endpoints
  db.py              # Подключение к PostgreSQL
  schemas.py         # Форматы ответов
db/init/
  001_schema.sql     # Таблицы и индексы
  002_seed.sql       # Импорт CSV
tests/
  test_bootstrap.py  # Проверки на реальной БД и HTTP API
docs/
  HACKATHON_PLAN.md
  DATA_AUDIT.md
compose.yaml
Dockerfile
requirements.txt
.env.example
```

Стек текущего этапа: Python 3.12, FastAPI, Uvicorn, Psycopg 3, PostgreSQL 16, Docker Compose. Версии прямых Python-зависимостей зафиксированы в `requirements.txt`.

Согласованный следующий этап: backend фильтрует каталог по обязательным условиям, затем `rank_candidates(request, eligible_candidates)` передаёт **всех** допустимых кандидатов AI-модулю участника 2. AI определяет состав и порядок TOP-3. Подробный [план на пять часов](docs/HACKATHON_PLAN.md).

`.env` исключён из Git и контекста Docker-сборки. API-ключи не должны попадать в код, браузер или репозиторий. Переменные OpenAI в `.env.example` зарезервированы для следующего этапа и пока не используются.
