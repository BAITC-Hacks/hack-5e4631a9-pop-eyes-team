# pop-Eyes — подбор подрядчиков для мероприятий

Проект команды pop-Eyes Team для HackAlem AI. Заказчик задаёт условия мероприятия и получает до трёх подрядчиков с объяснениями. Интерфейс, FastAPI и PostgreSQL соединены: справочники и карточки берутся из 66 профилей предоставленного CSV, демонстрационных ответов во frontend больше нет.

В репозитории есть AI-модуль участника 2 (`ai_module`). При пустом `AI_MODULE` по умолчанию работает явно обозначенный резервный подбор по начальной цене и ID. Он проверяет обязательные условия, но не оценивает пожелания и контекст. Для подключения модуля задайте `AI_MODULE=ai_module` и серверный API-ключ. Интерфейс `async rank_candidates(request, eligible_candidates)` получает всех допустимых кандидатов.

## Запуск

Нужны Docker Desktop с Linux containers и Docker Compose. Из корня репозитория, если `.env` ещё нет:

```powershell
Copy-Item .env.example .env
# Задайте POSTGRES_PASSWORD в .env.
docker compose up --build -d --wait
```

Существующий `.env` не перезаписывайте. При занятом порте измените `APP_PORT`. После первого создания БД смена пароля в `.env` сама по себе не меняет пароль PostgreSQL.

Если БД уже запускалась на предыдущей версии проекта, **перед запуском обновлённого app** добавьте таблицу сохранённых рекомендаций:

```powershell
docker compose up -d --wait db
docker compose exec db psql -U eventmatch -d eventmatch -v ON_ERROR_STOP=1 -f /docker-entrypoint-initdb.d/003_recommendations.sql
docker compose up --build -d --wait
```

Команда безопасна для повторного выполнения, профили сохраняются. При нестандартных `POSTGRES_USER` / `POSTGRES_DB` подставьте свои значения вместо `eventmatch`.

## Как работает подбор

1. Backend проверяет типы, справочники и известное календарное окно.
2. Из БД выбирается город и категория. Если такого сочетания нет — `category_absent`.
3. Строгие фильтры исключают неподходящих в порядке: дата → бюджет → формат → длительность → язык. Каждый исключённый профиль попадает только в один счётчик. Если никто не прошёл — `no_matches`.
4. Для непустого списка AI-модуль получает **всех** прошедших кандидатов, полные описания, разобранные числа/списки и пожелания. Предварительного сокращения до трёх нет.
5. Backend проверяет количество выбранных ID, уникальность, принадлежность допустимому списку, непустые объяснения и ссылки на факты соответствующих профилей. Порядок AI сохраняется. При отсутствии модуля, ошибке, таймауте или неправильном ответе включается `fallback`.
6. Имена, цены, категории и флаги карточек берутся из БД. Столбец `anon_name` преобразуется в `name` в карточке.
7. Проверенный ответ сохраняется в PostgreSQL до отправки клиенту.

Ключ сохранения включает нормализованный запрос (включая дату и пожелания), `dataset_version` и `recommendation_version`. Первый сохранённый результат выигрывает при одновременных запросах. Повторный запрос возвращает те же карточки, объяснения и порядок с `cache_hit=true`, включая после перезапуска с той же БД. Сохранённый fallback не заменяется незаметно; для новой версии AI измените `AI_VERSION`. Новая пустая БД не воспроизводит ранее потерянные AI-решения.

Полный контракт HTTP и AI: [docs/API_CONTRACT.md](docs/API_CONTRACT.md).

## Данные

Источник — [hackathon dataset anonymized .csv](hackathon%20dataset%20anonymized%20.csv), HTML-превью не используется. CSV читается стандартным `COPY` PostgreSQL при первом создании БД:

```text
001_schema.sql → таблицы contractors и dataset_metadata
002_seed.sql   → все 13 полей CSV, 66 профилей, типизация и контрольная сумма
003_recommendations.sql → сохранённые ответы подбора
```

Init-скрипты выполняются только на пустом томе. Обычный перезапуск использует сохранённую PostgreSQL, не читает CSV заново. HTTP API тоже читает БД, а не файл. Копия CSV внутри app используется интеграционным тестом для сверки импорта.

Все исходные поля сохранены: `id`, `anon_name`, `categories`, `city`, `city_imputed`, `synthetic`, `price_from_kzt`, `price_imputed`, `event_formats`, `languages`, `max_hours`, `busy_dates`, `description`. Списки преобразованы в массивы, числа и флаги — в соответствующие типы. Повторный импорт добавляет новые ID и обновляет существующие без дублей; отсутствующие в новом CSV записи автоматически не удаляет.

```powershell
docker compose exec db psql -U eventmatch -d eventmatch -v ON_ERROR_STOP=1 -f /docker-entrypoint-initdb.d/002_seed.sql
```

Импорт атомарен. Метаданные хранят SHA-256 исходного CSV и версию нормализованного каталога. Повторный импорт без изменения данных сохраняет версию. Обновляйте каталог через импорт, чтобы версия соответствовала данным.

Ограничения датасета:

- Доступность известна с **23.09.2026 по 31.12.2026 включительно**. Вне окна — HTTP 422.
- Цена — «от» за мероприятие, не окончательная смета; равенство бюджету допускается.
- `max_hours=null` означает неприменимость ограничения присутствия, не ноль часов.
- 13 синтетических профилей, 8 подставленных городов и 18 подставленных цен. Флаги отображаются на карточках.

Подробности и контрольные сценарии: [DATA_AUDIT.md](docs/DATA_AUDIT.md).

## Подключение AI-модуля

Модуль `ai_module` и его зависимости уже включены в Docker-образ. Для подключения настройте `.env`:

```dotenv
AI_MODULE=ai_module
AI_VERSION=prompt-v1
AI_MODE=auto
AI_TIMEOUT_SECONDS=5
OPENAI_API_KEY=your_key
OPENAI_MODEL=gpt-4o-mini
```

Модуль экспортирует асинхронную функцию `rank_candidates` и общую синхронную функцию `build_evidence(candidate)`. Требования и пример входа/выхода — в [контракте](docs/API_CONTRACT.md#интерфейс-ai-модуля), подробности реализации — в [AI_MODULE.md](docs/AI_MODULE.md). В асинхронной функции используйте неблокирующий клиент, иначе внешний таймаут не сможет остановить блокирующий вызов.

Пустой `AI_MODULE` либо `AI_MODE=fallback` включает резервный режим. После изменения настройки или кода пересоберите app. При изменении prompt, разбиения evidence или поведения модуля повышайте `AI_VERSION`, чтобы старый кэш не скрывал изменения. Ключи остаются на сервере; `.env` исключён из Git и Docker build context.

## Проверка

```powershell
docker compose ps
Invoke-RestMethod http://localhost:8000/health
docker compose exec app python -m unittest discover -s tests -v
```

Проверки сравнивают все поля CSV с реальной БД, выполняют HTTP-запросы, проверяют фильтры, пустые выдачи, ошибки 422, карточки, параллельное сохранение и повторяемость. Контракт AI проверяется тестовой функцией на четырёх реальных допустимых профилях; эти тесты не вызывают внешнюю модель и не доказывают качество настоящего AI.

Через форму: Алматы → Ведущий → 10.10.2026 → корпоратив → 1 млн ₸ даёт 4 допустимых кандидата и 3 карточки. На 19.12.2026 остаётся один. При бюджете 10 тыс. ₸ — `no_matches`; Астана + Декоратор — `category_absent`.

## Управление

```powershell
docker compose logs --tail=50 app db
docker compose up --build -d --wait
docker compose restart app
docker compose down
docker compose up -d --wait
```

Том `pop-eyes_postgres_data` сохраняет профили и решения после `down`. Не добавляйте `--volumes`, если данные нужно сохранить. Новые SQL-миграции существующей БД применяйте явно; повторный старт контейнера не исполняет init-скрипты заново.

Код: `app/main.py` — маршруты и статические файлы; `catalog.py` — чтение каталога; `recommendations.py` — фильтры и сохранение; `ranking.py` — подключение AI и fallback; `schemas.py` — HTTP-контракт. Frontend находится в `frontend/`, SQL — в `db/init/`, проверки — в `tests/`.

План команды: [HACKATHON_PLAN.md](docs/HACKATHON_PLAN.md). Публичный deployment не подготовлен. Наличие модуля в образе само по себе не включает AI-подбор: для него нужен `AI_MODULE=ai_module` и серверный ключ.
