# AI-модуль: подключение для участника 1

```python
from ai_module import build_evidence, rank_candidates, RECOMMENDATION_VERSION

result = await rank_candidates(request, eligible_candidates)
```

Python 3.11+. Зависимость `openai==2.54.0` зафиксирована в
`requirements-ai.txt`, включённом в общий `requirements.txt`.
Новых зависимостей для оценки качества не требуется.
Dockerfile копирует модуль, тесты и генератор тестовых данных; Compose передаёт настройки AI.

Модуль не подключается к БД, не импортирует CSV, не фильтрует и не сохраняет
решения. Backend передаёт **всех** прошедших строгие фильтры кандидатов.
Результаты проверки на реальном каталоге: [AI_EVALUATION.md](AI_EVALUATION.md).

## Согласованный контракт

`request` — словарь с `city`, `date`, `event_type`, `category`, `budget_kzt`,
`duration_hours`, `language`, `preferences` или соответствующая Pydantic v2-модель.
Дата в словаре может быть ISO-строкой или `datetime.date`; отсутствующие
пожелания превращаются в пустую строку. Backend валидирует запрос до вызова.

Каждый кандидат — словарь:

```python
{
    "id": str,
    "anon_name": str,
    "city": str,
    "categories": list[str],
    "price_from_kzt": int,
    "event_formats": list[str],
    "languages": list[str],
    "max_hours": float | None,
    "description": str,
    "synthetic": bool,
    "city_imputed": bool,
    "price_imputed": bool,
}
```

Цена — целое неотрицательное число, флаги — настоящие `bool`, списки уже разобраны.
Описание передаётся полностью. `max_hours` также принимает `int` и PostgreSQL
`Decimal`: общая функция `normalize_candidate` преобразует число в `float`,
сохраняя `None`. Поэтому SQL-строка и её JSON-представление дают одинаковые факты.
Входные объекты не изменяются. `busy_dates` и прочие дополнительные поля
игнорируются: доступность проверяет backend.

Форма результата не изменилась:

```json
{
  "selection_mode": "ai",
  "selected": [
    {
      "id": "HK-29829",
      "reason": "По пожеланию «развлечения и танцы»: в профиле указано «Только развлечения и танцы.».",
      "evidence_ids": ["HK-29829:description:2"]
    }
  ]
}
```

Здесь показан один элемент для иллюстрации. Фактическое количество всегда
`min(3, len(eligible_candidates))`; порядок модели сохраняется. Вход сортируется
по ID только для стабильной передачи модели, без предварительного TOP-3 по цене.

При пустом входе результат — `{"selection_mode": "fallback", "selected": []}`,
без сетевого вызова. Backend различает `category_absent` и `no_matches` **до** AI;
пустой результат нельзя показывать пользователю как сбой модели.

## Факты и объяснения

`build_evidence(candidate)` возвращает `{evidence_id: текст}`:

- `<id>:field:<поле>` — структурированные данные;
- `<id>:description:<номер>` — фрагменты описания в исходном порядке.

Код разбивает описание по предложениям, строкам и пунктам `•`, затем длинные
фрагменты — по границам слов до 180 символов. Весь текст сохраняется с нормализацией
пробелов. Очень длинное отдельное слово не разрывается и может превысить лимит;
слишком длинная выбранная цитата отклоняется. Все 66 текущих профилей укладываются
в лимит, потерь текста нет. Это технические фрагменты, не идеально выделенные факты.

Внутри AI-запроса используется более узкая схема: модель возвращает ID кандидата,
1–2 `evidence_ids` и `request_evidence_id`. Схема
разрешает только переданные ID и принадлежащие этому кандидату факты; если есть
описание, разрешены именно его фрагменты. Фрагменты пожеланий тоже создаёт код.
Итоговый `reason` код собирает из дословных цитат профиля и запроса, без свободного
пересказа моделью. Эти внутренние поля backend обрабатывать не нужно.

Проверяются количество, уникальность ID и ссылок, принадлежность фактов, длина
цитат и объяснения. Невалидный ответ целиком заменяется fallback.
У AI-объяснения 1–2 ссылки; у шаблонного fallback — **5** ссылок на цену, город,
форматы и флаги подстановки. Проверка backend должна принимать оба варианта.

Цитирование доказывает происхождение текста, но не достоверность рекламы профиля
и не точность оценки соответствия. Метки полного/частичного соответствия не ставятся:
для них нет надёжной автоматической проверки.
Смысловое качество проверяется отдельно; тесты не гарантируют отсутствие всех
ошибок ранжирования или устойчивость к любым prompt injection.

## Настройки и ошибки

| Переменная | По умолчанию |
| --- | --- |
| `OPENAI_API_KEY` | Пусто: fallback |
| `OPENAI_MODEL` | `gpt-4o-mini` |
| `AI_MODE` | `auto`; `fallback` отключает AI |
| `AI_TIMEOUT_SECONDS` | `8` |

Backend из `main` дополнительно требует `AI_MODULE=ai_module`; пустое значение
включает его собственный fallback. Для текущей версии задайте
`AI_VERSION=ranking-v5:evidence-v3:fallback-v1`: адаптер использует эту настройку
в ключе сохранения, а не читает экспортированную константу автоматически.
Подробности подключения: [API_CONTRACT.md](API_CONTRACT.md).

`.env` загружает приложение, Compose или команда ниже; сам пакет файл не читает.
Ключ используется только на сервере, не попадает в ответы и отчёты.

Один асинхронный вызов OpenAI Responses API с Structured Outputs,
`store=False`, без повторов SDK. `asyncio.wait_for` ограничивает весь вызов
восемью секундами по умолчанию. Подготовка входа и локальные проверки выполняются
отдельно; это не гарантия времени полного HTTP-запроса. Уменьшение объёма генерации
и ограничения схемы соответствуют официальным рекомендациям:
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[снижение задержки](https://developers.openai.com/api/docs/guides/latency-optimization).

Ошибка API, отказ, таймаут, неполный/невалидный ответ дают `selection_mode="fallback"`.
Резерв сортирует по начальной цене, затем ID; подставленные город и цена отмечаются.
Логи содержат класс ошибки без ключа, текста запроса и ответа провайдера.
Отмена вызывающей задачи распространяется наверх.

Неверные типы входа или настройки — ошибки интеграции (`ValueError`, `KeyError`,
`TypeError`), а не штатный fallback. UI для непустого fallback:
«AI-подбор временно недоступен; показаны подходящие варианты по начальной цене».

## Что подключает backend

1. Отфильтровать каталог и обработать пустые бизнес-исходы.
2. Найти сохранённое решение по полному запросу и версиям. При промахе вызвать
   `await rank_candidates(request, eligible_candidates)`.
3. Проверить количество, уникальность и допуск ID; для каждой ссылки проверить
   членство в `build_evidence(by_id[item["id"]])`.
4. Собрать карточки из БД (`anon_name`, цена «от», флаги происхождения).
   Сохранить порядок `selected`, причины, ссылки и `selection_mode` атомарно.
5. При повторе вернуть сохранённый результат, включая fallback, без скрытой замены.

Текущая версия: `ranking-v5:evidence-v3:fallback-v1`.
Экспортируются `PROMPT_VERSION`, `EVIDENCE_VERSION`, `RECOMMENDATION_VERSION`.
Ключ сохранения включает `RECOMMENDATION_VERSION`, `OPENAI_MODEL`, `dataset_version`,
версию фильтров и весь запрос, в том числе пожелания, дату, язык и длительность.
Изменение описания может сдвинуть номера фактов: старый кэш с новой версией не смешивать.
Сохранение и конкурентные запросы реализует участник 1.

## Воспроизводимые проверки

Из корня проекта, без ключа и сетевых запросов:

```console
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p "test_ai*.py" -v
python scripts/build_ai_fixtures.py --check
python -m ai_module.evaluate
```

Фикстуры в `tests/fixtures/ai` содержат реальные профили после условий контрольных
сценариев. Генератор — только инструмент тестирования; он не заменяет SQL-импорт
или фильтры backend. Его контрольная сумма `source_sha256_lf` нормализует CRLF в LF,
чтобы Windows и Linux давали одинаковый результат. После изменения каталога
пересчитать аудит, обновить эталонную сумму и выполнить генератор без `--check`.

Для реальных вызовов загрузить переменные без вывода ключа:

```powershell
foreach ($line in Get-Content -LiteralPath .env -Encoding UTF8) {
    if ($line -match '^\s*(OPENAI_API_KEY|OPENAI_MODEL|AI_MODE|AI_TIMEOUT_SECONDS)\s*=\s*(.*?)\s*$') {
        [Environment]::SetEnvironmentVariable(
            $Matches[1], $Matches[2].Trim().Trim([char]34).Trim([char]39), 'Process')
    }
}
$env:PYTHONIOENCODING = 'utf-8'
.\.venv\Scripts\python.exe -m ai_module.evaluate --live --output .venv/ai-evaluation.json
```

Загрузчик рассчитан на простые строки `ИМЯ=значение` без комментариев после значения.
`--live` делает платные API-вызовы и принудительно включает `AI_MODE=auto` на время
оценки. Без него проверяется только fallback. Любой fallback в непустом live-сценарии
считается ошибкой; отчёт сохраняется и команда завершается с ненулевым кодом.
Для двух контекстов: `--cases hosts_business hosts_party`.

В контейнере с уже загруженными настройками:

```console
docker compose exec app python -m ai_module.evaluate --live
```

Для экспортированных backend данных (`request` + `eligible_candidates`):

```console
python -m ai_module.smoke --input path/to/eligible.json --require-ai
```

Без `--input` smoke использует четыре синтетических тестовых профиля.
Полный HTTP-сценарий, БД, кэш и Docker проверяются совместно после подключения backend.
