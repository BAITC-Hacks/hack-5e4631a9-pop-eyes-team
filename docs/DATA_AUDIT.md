Источник: `hackathon dataset anonymized .csv`, предоставленный командой.

HTML-превью используется только для ознакомления, CSV — источник структурированных данных.

## Состав

- 66 записей и 66 уникальных ID, 13 столбцов.
- 50 профилей в Алматы, 15 в Астане, 1 с городом «Зарубежье».
- 17 категорий. Один профиль может иметь несколько категорий.
- 13 синтетических профилей, 8 с подставленным городом, 18 с подставленной ценой.
- Пустых описаний нет. Цены «от»: 100 000–6 000 000 тенге за мероприятие.
- Календарное окно по ТЗ: 2026-09-23–2026-12-31 включительно. Все даты занятости успешно разобраны как ISO-даты и находятся в этом окне.
- Пустой `max_hours`: 3 флориста, 3 декоратора, 3 профиля подарков/сувениров. По ТЗ это неприменимость ограничения присутствия, а не ноль часов.
- `categories`, `event_formats`, `languages`, `busy_dates` разделены символом `|`. CSV следует читать CSV-парсером.
- Значения флагов представлены строками `True`/`False`; преобразовывать явно.

Во всех запросах формат — «корпоратив», язык и длительность не заданы.

## Семантика для реализации

- Сначала проверить наличие пары город + категория, затем остальные ограничения: так различаются два пустых исхода.
- Для объяснения исключений использовать непересекающиеся счётчики по порядку: дата → бюджет → формат → длительность → язык. Каждый кандидат учитывается один раз. При желании сохранять и все причины отдельно, явно обозначая пересечение.
- Не ослаблять ограничения автоматически и не дополнять выдачу занятыми подрядчиками.
- За пределами календарного окна сообщать, что данных о занятости нет; не считать отсутствие даты доказательством свободы.
- Бюджет сравнивать с начальной ценой. Не обещать окончательную стоимость мероприятия.
- Структурированные поля определяют допуск. Рекламный текст описания не отменяет ограничения полей.
- При изменении исходных данных или политики ранжирования пересчитать ожидаемые ID.
